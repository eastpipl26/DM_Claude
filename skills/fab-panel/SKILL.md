# /fab-panel — 공종 패널 토론

## 목적

공종 간 충돌·간섭·트레이드오프가 있는 FAB 설계 이슈를 여러 공종 관점에서 독립 검토 → 상호 반박 → 종합하는 파이프라인.

## 사전 확인

1. `{claude_home}\config.md` Read — 경로 변수.
2. 이슈가 정말 공종 간(2개 이상)인지 판정. 단일 공종이면 이 스킬을 쓰지 않고 archie에게 직접 위임 (저비용 경로).

## 파이프라인

### 0. 진행자 지정
archie 에이전트를 진행자로 스폰 (run_in_background: true). 이하 절차는 archie가 수행한다.

### 1. 공종 선별
이슈와 관련된 공종만 선별한다. 전 공종 소집 금지 — 관련 없는 공종을 부르면 토큰 낭비.

| 공종 | 지식 파일 |
|---|---|
| 건축 | `{knowledge}\fab\architecture.md` |
| 구조 | `{knowledge}\fab\structure.md` |
| UT | `{knowledge}\fab\ut.md` |
| 전기 | `{knowledge}\fab\electrical.md` |
| 소방 | `{knowledge}\fab\fire.md` |

(pm.md는 진행자 archie 자신이 로드 — 조정 원칙·간섭 사례.)

### 2. 1라운드 — 독립 검토 (병렬)
선별된 공종 수만큼 범용(general-purpose) 서브에이전트를 **병렬** 스폰. 각 프롬프트에 포함:
- 이슈 전문 + `{claude_home}\rules\domain-fab.md` 읽으라는 지시
- 자기 공종 지식 파일 경로 (그 파일만 로드)
- "타 공종 의견 없이 자기 공종 관점의 검토의견·리스크·요구사항을 작성하라. 지식 파일에 '확인 필요'로 표시된 수치는 단정하지 말라."
- **서로의 의견을 보여주지 않는다** (앵커링 방지).

### 3. 2라운드 — 상호 반박·보완
1라운드 전체 의견을 모아 각 패널에게 다시 전달 (foreground 순차 또는 병렬):
- "타 공종 의견 중 자기 공종과 충돌하는 지점을 지적하고, 수용 가능한 대안을 제시하라."
- 쟁점 없는 공종은 "이견 없음"으로 짧게 종료 가능.

### 4. 종합 보고 (archie)
- **결론 먼저**: 합의안 한 줄.
- 공종별 입장 · 트레이드오프 · 최종 권고 구분 명시.
- 합의 안 된 쟁점은 "미해결 쟁점"으로 분리 — 억지 합의 금지.
- "확인 필요" 항목 목록 (원문 대조 필요한 수치).

### 5. 저장·보고
- 토론 결과: `{issues}\YYMMDD_{phase}_{building}_{키워드}.md` 또는 `{fab_docs}\{주제}.md` (설계 기준으로 남길 가치가 있으면 후자).
- 완료 보고에 저장 절대경로 포함.

## 비용 규칙

- 라운드×공종 수만큼 토큰 소모 — 시작 전 소집 공종 수를 보고하고 진행.
- 2라운드에서 쟁점이 없으면 3라운드 없이 종합으로 직행.
