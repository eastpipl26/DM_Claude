회의록의 각 안건은 다음 형식으로 정리한다.

```
## [프로젝트/Phase 태그] 안건 제목

1. 첫 번째 논의 포인트
   1. 세부 내용(있으면 하위 번호로)
2. 두 번째 논의 포인트
3. (내용 없으면 번호만 적고 비워둠)
```

- **안건 제목(## 헤더) 앞에는 번호를 붙이지 않는다** — `[Y-1 Ph1]`처럼 프로젝트/Phase 태그만 붙인다. 번호매김은 안건 내부 논의 포인트에만 적용.
- Phase 표기는 `Ph1`, `Ph2`처럼 하이픈 없이 쓴다. 단 `Y-1`은 예외로 하이픈을 유지한다(예: `[Y-1 Ph1]`).
- 논의 포인트는 불릿(`-`)이 아니라 **번호 리스트**로 적는다. 세부사항은 하위 번호로 들여쓴다.
- 내용이 아직 없는 안건은 번호(1.)만 적어두고 비워둔다 — 회의 진행하며 채워짐.
- 표(장단점 비교 등)나 결론 굵게 표시는 기존처럼 유지 가능, 다만 목록 형태 내용은 번호매김이 기본.

**Why:** 도요님이 실제 사내 보고서·이메일에서 쓰는 형식이 번호매김 리스트라, 회의록도 같은 형식으로 맞추면 그대로 보고서에 옮겨쓰기 편함.

**How to apply:** 앞으로 모든 회의록(`20_Projects\SK하이닉스_용인\회의록\*.md`)은 이 양식을 기본으로 사용한다. [[feedback-meeting-workitem-timing]]과 함께 적용 — 회의 진행 중엔 이 양식으로 안건만 쌓고, 회의 종료 선언 후 업무리스트에 반영한다.
